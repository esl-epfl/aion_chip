# The AION flow handler

Seven steps that turn `src/rtl/` into a chip built from AI-generated standard
cells. Everything they produce lands in `flow/`.

```bash
./flow.py                      # the whole chain
./flow.py 3                    # one step
./flow.py 2..5                 # a range
./flow.py 5-                   # step 5 to the end
./flow.py 6 --draw auto        # let an agent draw the layouts
./flow.py 6 --draw auto -j 3   # ... three cells at a time
./flow.py status               # is this flow coherent?
./flow.py --list               # what the steps are
./flow.py --dry-run            # print every command, run nothing
```

`make flow`, `make flow STEP=3`, `make flow STEP=6 FLOW_ARGS=--draw=auto`,
`make flow-status` and `make flow-list` are the same thing from the Makefile.

Steps can be named by number (`3`), by full name (`3_rewrite`) or by a unique
prefix of the name (`rew`). Ranges are `2..5` (inclusive) or `5-` (to the end).

### Options

| Flag | Effect |
|---|---|
| `--set NAME=VALUE` | override a flow variable; repeatable. See [Every setting](#every-setting). |
| `--draw manual\|auto` | step 6 only: hand-drawn (default) or agent-drawn layouts |
| `--draw-jobs N`, `-j N` | step 6 only: cells to work on at once (default 1). In `--draw auto` that is N agent sessions in parallel. |
| `--lenient` | downgrade LibreLane's hard checkers to warnings. Never for signoff. |
| `--force` | run without the stale-upstream warning |
| `--dry-run` | print every command and run nothing — no tools, no model tokens |
| `--quiet` | do not echo tool output to the terminal; it still goes to `flow/logs/` |
| `--timeout SECONDS` | per-command wall clock (default 4 h) |
| `--status` | print the coherence table and exit (same as `./flow.py status`) |
| `--list` | list the steps and exit |

A step is never silently skipped: if you name it, it runs.

## Before anything

The EDA container must be running — `ngspice`, `magic`, `netgen`, `klayout`,
`librelane` and `kepler-formal` are only in there:

```bash
docker start iic-osic-tools_shell_uid_1000
source env.sh                  # conda env for yosys/ghdl/iverilog/verilator/fusesoc
```

The flow checks for the container up front and tells you, rather than failing
halfway through a step.

## The steps

| # | Step | What it does | Typical time |
|---|------|--------------|--------------|
| 1 | `1_synth` | LibreLane synthesis + pre-PnR STA, then a post-synthesis simulation | ~1 min |
| 2 | `2_pattern_extraction` | mine recurring subgraphs, emit a cell library, cut it to `ELITE_COUNT` | seconds |
| 3 | `3_rewrite` | substitute the cells, prove equivalence (LEC), re-simulate | ~1 min |
| 4 | `4_characterization` | exhaustive SV and SPICE testbenches per cell | seconds |
| 5 | `5_gate_minimization` | re-implement each cell as one CMOS stack, proved in SPICE | seconds–minutes |
| 6 | `6_layout_drawing` | draw, verify, characterize and publish each cell's views | minutes–hours |
| 7 | `7_pnr` | harden the netlist with those cells, then simulate with SDF | ~10 min |

Every step reads only what it declares, writes only under its own directory
(step 6 also publishes into `implementation/cells/`), and never assumes an
earlier step ran in the same process.

## What lands where

```
flow/
  coherence.json              what ran when, and whether it still adds up
  logs/<step>/*.log           one file per command the handler ran
  aion_cells.core             regenerated by step 6 (FuseSoC handle on the models)

  1_synth/            nl/ sdf/ reports/ metrics.json
  2_pattern_extraction/   aion_cells.v  aion_cells_elite.v
                          work/selection.json  report/pattern_report.json
  3_rewrite/          nl/{aion_cells.v, tt_um_aion.nl.v}  report/
  4_characterization/ steps/aion_char/tb/{sv,spice}/  gold_functions.md
  5_gate_minimization/ raw_spice/  minimized_spice/
  6_layout_drawing/   <CELL>/{drc,lvs,pex,char,baseline,final}/
  7_pnr/              nl/ sdf/ gds/ def/ reports/ metrics.json
  pnr_simple/         the PDK-only baseline (make pnr_simple, not a step)
```

`flow/logs/` is deliberately *outside* the step directories: `make synth` and
`make pnr` both end in `_save_run`, which does `rm -rf` on the step directory,
so a log written inside it would be deleted while still being written.

`3_rewrite/nl/aion_cells.v` is the **library of record** — exactly the cells
the netlist instantiates. Steps 4, 5 and 6 read that copy rather than step 2's
output, so a hand-curated selection propagates without being re-derived.

## Steps 2 and 3 are separate on purpose

Step 2 mines every cell it can find and cuts an elite library down to
`ELITE_COUNT`. Step 3 is what commits to a set, because **every cell that
survives into the netlist is a cell someone has to draw by hand in step 6**.

Step 2 prints the cover ranked by area saved:

```
cell                              uses   saved um2   elite
AION_nand2_o21ai_0                  91       222.9   yes
AION_a21oi_nor2_1                   56       137.2
AION_nand2b_o21ai_2                 28        76.2
```

To take the top N by rank, just set `ELITE_COUNT`. To pick cells *by name*:

```bash
./flow.py 2
cp flow/2_pattern_extraction/aion_cells.v flow/my_cells.v
$EDITOR flow/my_cells.v          # delete the modules you do not want
./flow.py 3 --set REWRITE_CELLS=flow/my_cells.v
```

Keep each `// AION canonical_key:` comment attached to its `module` line —
that is what the rewriter matches on, not the module name — and keep any
`// AION complement_inputs:` line with it. Deleting a module leaves its sites
as ordinary PDK cells. You do not need to touch `selection.json`; the cell
library is not part of its fingerprint, which is exactly what makes this cheap.

`REWRITE_CELLS=elite` (the default) and `=all` pick step 2's two outputs.

## Step 6, and the one thing a model does here

Exactly one artifact in this flow is authored rather than computed:

```
aion_flow/tools/aion_layout_claude/cells/<CELL>.py
```

a module exposing `generate(name, tech) -> Cell`. Everything else — DRC, LVS,
PEX, the abutted PDK baseline, characterization, the comparison, the view
export — is mechanical, has exactly one right answer, and the handler runs it
on the host. The agent's own account of what it did is never the verdict; the
verdict is this step's own `make verify` and the single `RESULT:` line it
prints.

**`--draw manual` (default)** scaffolds the generator, prints the
edit → verify → evidence loop, and marks the step `WAITING`. Draw it, then
re-run `./flow.py 6` to finish the mechanical chain.

```bash
export AION_CONTAINER_MOUNT=/foss/designs/aion_chip/aion_flow
TOOL=aion_flow/tools/aion_layout_claude
make -C $TOOL verify   CELL=<CELL> NETLIST=<...> BUILD_DIR=<...>
make -C $TOOL evidence CELL=<CELL> NETLIST=<...> BUILD_DIR=<...>
```

(step 6 prints these two lines filled in, so you can paste them.)

**`--draw auto`** runs that loop with `claude -p` and the `aion-layout` skill,
up to `DRAW_MAX_ITERS` turns, grading the *file on disk* after every turn —
not the agent's exit status, because an agent that timed out after writing a
complete generator has done the work. If two turns in a row leave the
generator untouched the step stops and says so, rather than burning the
remaining turns: that means the agent is not running (no quota, no
credentials, a refusal), which is a different problem from a hard layout.

It draws with `DRAW_MODEL` at `DRAW_EFFORT` — Opus 5 at high effort by
default. The generator is the one artifact in this flow that nothing can
compute, and every turn costs a container DRC/LVS round trip whatever model
wrote it, so a weaker model mostly buys more turns:

```bash
./flow.py 6 --draw auto --set DRAW_MODEL=claude-sonnet-5 --set DRAW_EFFORT=max
./flow.py 6 --draw auto --set DRAW_MODEL=none    # whatever your CLI defaults to
```

Each turn is narrated while it runs — the tools the agent calls, the verdict
lines they print back, and a `… still working` heartbeat when one container
call takes minutes:

```
  ▶ claude -p  (turn 3/12, AION_mux2_3)
    00:00  session 8cb8c267  model claude-opus-5  30 tool(s)
    00:04  ⚙ Read  cells/AION_mux2_3.py
    00:21  ⚙ Bash  make -C tools/aion_layout_claude verify CELL=AION_mux2_3 …
    02:57  ✖ RESULT: FAIL
    03:04  ⚙ Edit  cells/AION_mux2_3.py
    …
    24:11  claude exit 0  31 turn(s)  $1.87  session 8cb8c267
```

The same stream is teed to `flow/logs/6_layout_drawing/<CELL>.agent.<n>.log`
as it arrives, so `tail -f` works and an interrupted turn still leaves its
whole history behind. `--set DRAW_STREAM=false` goes back to one block at the
end, and `--quiet` drops the terminal half while keeping the log.

**`-j N` / `--draw-jobs N`** works on N cells at once — in `--draw auto`, N
agent sessions in parallel. Cells share nothing but the EDA container and the
terminal: their own build directory, their own generator, their own session.
Every line is tagged with the cell it came from:

```
[mux2_3      ]   ▶ claude -p  (turn 2/12, AION_mux2_3)
[nand2_o21ai ]     03:12  ⚙ Bash  make -C tools/aion_layout_claude verify …
[mux2_3      ]     00:08  ⚙ Edit  cells/AION_mux2_3.py
```

Each session also drives the container with `LAYOUT_JOBS` ngspice jobs of its
own, so N multiplies that; 2–4 is a sensible range on a workstation. One cell
failing no longer takes the others down — it is reported as that cell's
result, and the step still fails at the end. Ctrl-C stops every agent and
every container call it started, not just the one the flow was watching.

A published cell needs `.lef`, `.lib` and `.gds`; `.v`, `.spice` and `.cdl`
come with them. They land in `implementation/cells/<CELL>/`, which is where
`make pnr` looks. `COMPARE: LOSS` (the cell is bigger or slower than the
abutted PDK cells it replaces) is a real result, not an error — the views are
complete either way, and the cell is still published unless you set
`DRAW_PUBLISH_ON_LOSS=false`.

## Coherence

Each step records when it finished, the knobs it ran with, and a content
digest of every file it consumed and produced. A step is **stale** when an
upstream step finished after it did, or when a file it consumed no longer
hashes to what it hashed at the time.

```
$ ./flow.py status

  step                    state       finished
  1_synth                  OK        2026-09-06T18:38:32+02:00
  2_pattern_extraction     STALE     2026-09-06T18:38:33+02:00
      · 1_synth re-ran at 2026-09-06T19:02:11+02:00
```

Staleness is transitive: re-running synthesis marks step 6 stale too, even
though step 6's direct input (step 5) has not moved.

The flow **warns loudly and runs anyway**. Re-running one step in isolation is
the normal way to work here, so the warning is the point, not a gate. `--force`
silences it.

Digests hash file *content*, not mtimes, so a branch switch or an editor
save-without-change does not cry stale.

## Configuration

Every knob lives in `config.py`, in the same shape as
`aion_flow/examples/full_flow/flow.py`. Override any of them per run:

```bash
./flow.py 2 --set ELITE_COUNT=2 --set MAX_SIZE=4
./flow.py 7 --set SDF_CORNER=nom_typ_1p20V_25C
./flow.py 1..7 --lenient
```

Values are type-checked, and settings with a fixed set of choices are
validated, so `--set DRAW_MODE=Auto` is an error rather than a silent fallback
to manual.

### Every setting

| Setting | Default | Step | What it does |
|---|---|---|---|
| `TOP` | `tt_um_aion` | all | top-level module name |
| `LENIENT` | `False` | 1, 7 | downgrade LibreLane's hard checkers to warnings. Never for signoff. |
| `TIMEOUT` | `14400` | all | per-command wall clock, seconds |
| `SYNTH_SIM_TOOL` | `verilator` | 1, 3 | `verilator` or `icarus` |
| `MAX_SIZE` | `3` | 2, 3 | cells per mined pattern (2–8) |
| `MIN_OCCURRENCES` | `2` | 2, 3 | times a pattern must be mined to be kept |
| `MIN_SELECTED` | `None` | 2, 3 | times it must survive the cover (`None` = same as `MIN_OCCURRENCES`; `1` disables) |
| `AREA_FACTOR` | `0.65` | 2, 3 | assumed area of a merged cell vs the gates it replaces |
| `MAX_OUTPUTS` | `1` | 2, 3 | boundary outputs per pattern (`None` = no limit) |
| `MAX_INPUTS` | `5` | 2, 3 | boundary inputs per pattern (`None` = no limit) |
| `JOBS` | `None` | 2, 3 | mining workers (`None` = every core) |
| `CELL_PREFIX` | `AION_` | 2, 3 | prefix of every generated module (the rewriter emits `_AION_` as the instance prefix). |
| `ELITE_COUNT` | `5` | 2 | size of the elite library (`None` = keep every cell) |
| `ELITE_METRIC` | `saved-area` | 2 | `saved-area`, `occurrences` or `saved-area-per-cell` |
| `REWRITE_CELLS` | `elite` | 3 | `elite`, `all`, or a path to a hand-curated `.v` |
| `REWRITE_FLAT` | `False` | 3 | also emit the flattened netlist (only needed for a sequential equivalence check) |
| `LEC_LIB` | `None` | 3 | Liberty the LEC reads (`None` = the tool's own default). Mapped into the container for you. |
| `MINIMIZER_MODE` | `transistor` | 5 | `transistor`, `area` (identical to it) or `balance` |
| `MINIMIZER_WN` / `_WP` / `_L` | `0.74u` / `1.48u` / `0.13u` | 5 | device sizing for the re-implemented cell |
| `MINIMIZER_MAX_INPUTS` | `6` | 5 | refuse cells wider than this; verification is 2^inputs vectors |
| `MINIMIZER_VERIFY` | `True` | 5 | exhaustive switch-level equivalence, pure Python, no simulator |
| `MINIMIZER_VERIFY_SPICE` | `True` | 5 | the real ngspice 3-way check per cell. Slow, and why step 5 needs the container. |
| `LAYOUT_CORNERS` | `typ` | 6 | `typ` or `all`. **Keep `typ`** — see below. |
| `LAYOUT_JOBS` | `8` | 6 | parallel ngspice jobs during characterization |
| `DRAW_MODE` | `manual` | 6 | `manual` or `auto` |
| `DRAW_JOBS` | `1` | 6 | cells worked on at once (`-j N`); in `auto`, parallel agent sessions |
| `DRAW_STREAM` | `True` | 6 | narrate each agent turn while it runs |
| `DRAW_MAX_ITERS` | `12` | 6 | agent turns per cell before giving up |
| `DRAW_TIMEOUT` | `1800` | 6 | seconds per agent turn |
| `DRAW_MODEL` | `claude-opus-5` | 6 | the model that draws (`None` = the CLI's own default) |
| `DRAW_EFFORT` | `high` | 6 | thinking effort per turn: `low`, `medium`, `high`, `xhigh`, `max` (`None` = leave the CLI's setting alone) |
| `DRAW_PUBLISH_ON_LOSS` | `True` | 6 | publish a cell that lost the area/delay comparison |
| `LAYOUT_VERIFY_PEX` | `True` | 6 | re-prove the extracted layout's function in SPICE |
| `SDF_CORNER` | `nom_slow_1p08V_125C` | 7 | also `nom_typ_1p20V_25C`, `nom_fast_1p32V_m40C` |
| `PNR_SIM_TOOL` | `icarus` | 7 | `icarus` keeps the SDF delays; `verilator` drops them |

Three of those decide whether the flow works at all:

- **`ELITE_COUNT`** — every kept cell costs a drawn layout, so this is the
  knob that decides how long step 6 takes. `--draw-jobs` buys some of that
  back by drawing them in parallel.
- **`LAYOUT_CORNERS = typ`** — `all` makes the exporter publish one Liberty
  per corner, and `make pnr` groups cell views by file stem, so the extra
  `.lib` files become phantom cells with no LEF and PnR refuses to start. The
  cost of pinning it: LibreLane reads that one typ Liberty into all three STA
  corners, so setup at slow and hold at fast are characterized with typ data.
- **`DRAW_MODE = manual`** — so a plain `./flow.py` never silently spends
  model tokens.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | every requested step completed |
| 1 | a step failed (or, for `status`, something is stale) |
| 3 | finished, but a step is `WAITING` on you — step 6 with an undrawn cell |
| 4 | the EDA container is not running |
| 130 | interrupted |

So `./flow.py 6 && ./flow.py 7` does the right thing: a step that is merely
waiting does not pretend to have succeeded.

## Two path namespaces, and why

Steps run in one of two places, and mixing them up is silent rather than loud:

```
host       /home/<you>/phd/aion/aion_chip/flow/1_synth/nl/x.v
container  /foss/designs/aion_chip/flow/1_synth/nl/x.v
```

`paths.container()` is the only conversion and it refuses anything outside the
project, because nothing else is reachable from inside the container under a
name this flow can rely on.

The reason it is aion_chip's mount and not aion_flow's: the container has
`/foss/designs/aion_flow` bound to a **separate standalone checkout**, not to
the submodule. `aion_flow/scripts/docker_run.sh` and two `$(subst ...)` lines
in its Makefile hardcode that path, so driving them from here would read
inputs and write outputs in the wrong tree without ever saying so. The handler
therefore routes every containerised step through **aion_chip's own**
`scripts/docker_run.sh`, which lands in `/foss/designs/aion_chip/aion_flow`
and exports `AION_IN_DOCKER=1` — the flag that also stops aion_flow's Makefile
from rewriting our paths. The layout tool is the one piece with a proper
override, so it gets `AION_CONTAINER_MOUNT` instead. **No edits to the
submodule's Makefile are needed.**

## Two things the submodule needed

Both are one file each, and both are load-bearing:

**`aion_flow/FUSESOC_IGNORE`** — `fusesoc.conf` declares
`[library.aion] location = .`, which walks the whole project including the
submodule. `aion_flow/tech/tech.core` declares the same VLNV as
`aion_chip/tech/tech.core` — `epfl:aion:tech:1.0.0` — but points at the
*timing* cell models. The submodule won by walk order, so every gate-level
simulation silently elaborated with the wrong models and Verilator hung at
0 ns. FuseSoC skips any tree containing a file with this name. **It is
untracked in the submodule; commit it there so a fresh clone has it.**

**`implementation/config.json` → `RSZ_DONT_TOUCH_RX`** — must stay at its
default. It was once `^aion_.*`, which matched nothing (the regex matches
*instance* names, and `aion_opt`'s rewriter emits `_AION_0_`). Correcting it
to `^_AION_.*` made it match — and broke step 7: don't-touch on an instance
also forbids buffering its input pins, so `repair_design` aborts with RSZ-3006
on the first high-fanout net driving an AI cell. See `implementation/cells/README.md`
for why the cells survive without it.

## Troubleshooting

**`the EDA container ... is not running`** — `docker start iic-osic-tools_shell_uid_1000`.

**A step says `STALE UPSTREAM`** — an earlier step re-ran or its inputs
changed. Either re-run the upstream steps, or pass `--force` if you know the
change does not matter.

**Step 3 fails with "the rewrite substituted nothing"** — the mining knobs in
step 3 must match step 2's exactly, or the selection cache's fingerprint stops
matching and a different cover is mined. If you curated the library by hand,
check the `// AION canonical_key:` comments are still attached to their
modules.

**Step 6 stops with "the drawing agent made no change twice in a row"** — the
agent is not running at all. Read
`flow/logs/6_layout_drawing/<CELL>.agent.*.log`; it is usually a quota or
credentials problem, not a layout problem.

**Step 7 refuses with "cells that have no published views"** — the netlist
instantiates cells step 6 has not drawn yet. Finish step 6, or re-run step 3
with a library containing only cells you have drawn.

**A simulation passes suspiciously fast** — check the tail for
`cocotb: N/N test(s) passed`. Without that line the run did not reach the
testbench. The simulators exit 0 whether tests pass or fail, so the Makefile
reads `results.xml` and fails on `<failure>` elements; that check is what makes
a green run mean something.
